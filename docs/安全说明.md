# 安全说明：数据会不会泄露

这份文档回答一个问题：**用这套规则，我的数据安全吗？**

先给结论，再给依据，最后告诉你**怎么自己验证**（不用信我）。

| 层次 | 风险 | 说明 |
| :-- | :-- | :-- |
| **这个仓库本身** | **无** | 它只下载公开的规则文本，不上传任何东西；产物里不含节点和密码 |
| **① 域名层**（不用证书） | **无** | 只做域名匹配和拦截，**不触碰你的流量内容** |
| **② 模块层**（需要证书） | **有，但边界明确** | 开启 HTTPS 解密后，被解密域名的内容对手机上的小火箭和它加载的脚本是明文的 —— 详见下文 |

**一句话**：不想承担任何风险，就**别装模块层**（域名层已经能拦掉大部分广告）。
想用模块层，就用下面的办法把风险缩到最小。

---

## 一、这个仓库会不会上传我的数据？

**不会。** 而且这一点是可验证的，不需要你信任作者：

1. **它的全部网络行为就是"下载"**：从 15 个公开 URL 拉规则文本。代码里所有网络调用都在
   `src/util.py` 里的一处 `download()` 函数，只发 GET 请求。
2. **它不采集、不统计、不上报任何东西**（没有埋点、没有遥测、没有第三方 SDK）。
3. **产物里不允许出现敏感信息**：每次构建都会自动扫描 `dist/` 和 `vendor/`，
   只要检出节点定义、密码、订阅令牌就**直接判定构建失败、不发布**。
   这条检查的存在本身就是为了防止"你自己的节点信息被误提交到公开仓库"。
4. **GitHub Actions 只往你自己的仓库推产物**，不涉及任何第三方服务。

---

## 二、域名层：为什么它是安全的

域名层（`ad-domain.list` + `ad-rule.list`）**不需要装证书、不开解密**。
它做的事只有一件：**按域名决定这个请求该直连、该走代理、还是该拦掉**。

你的 HTTPS 流量对它**始终是加密的** —— 它看不到你在传什么、也改不了内容。
即使这份规则被人恶意篡改，最坏的结果也只是"某个域名被拦 / 被放行"，**无法读取你的任何数据**。

**所以：只装域名层，就不存在隐私风险。** 代价是开屏广告和改包类去广告用不了。

---

## 三、模块层：这才是真正的风险，但边界是清楚的

模块层要做的事，本质上就是 **让一个 App 解密你的 HTTPS 流量**（MITM）。
风险来自两个地方：

### 3.1 解密本身：是本地的，不上传

小火箭在**你手机本地**完成"解密 → 改写 → 重新加密"，内容不会因此被发到任何地方。
这一步本身不泄露 —— 但它意味着：**被解密的那些域名，内容对手机上的小火箭是明文的**。

风险边界 = **你解密了多少域名**：

| 装法 | 解密的主机名 | 一句话 |
| :-- | --: | :-- |
| 只装 `ads-all` 总模块 | **1,010 个** | 覆盖约 700 款 App，最省事、范围最大 |
| 只装你需要的几个 per-App 模块 | **几个到几十个** | 推荐。每个 App 的模块只解密它自己的域名 |
| 装 `mitm-exclude` 排除掉 | 减去排除的 | **已预置 45 个银行/券商/支付/办公域名**，装上就生效；要加自己的在「编辑参数」里填 |

### 3.2 脚本：它们能读到被解密的内容

模块里 231 条规则会执行**第三方 JS 脚本**（83 个，来自 12 个 GitHub 仓库）。
脚本运行在小火箭的 JS 环境里，**能读到被解密请求和响应的内容**。

这才是真正需要审视的地方。我对这 83 个脚本做了静态审计，**能证明**的事情如下：

| 审计项 | 结果 |
| :-- | :-- |
| 完全不含网络 API 的脚本（只改写响应体，**没有外发数据的能力**） | **75 / 83** |
| 含网络 API 的脚本 | 8 / 83 |
| 出现 GitHub 之外域名的脚本 | 9 / 83（清单见下） |
| **含"把请求/响应内容 POST 出去"代码路径的脚本** | **0 / 83** |

第三行那个清单很关键 —— 它列出了"如果你装了对应模块，哪些域名会看到你的请求"：

| 脚本 | 涉及域名 | 判断 |
| :-- | :-- | :-- |
| `keep.js` / `kuwo.js` / `rrtv_json.js` / `bilibili.json.js` | 各自 App 自己的域名（keepland.com、kuwo.cn、rr.tv、hdslb.com） | 正常，就是它要处理的站点 |
| `BahamutAnimeAds.js` | api.gamer.com.tw | 巴哈姆特自己的 API |
| `adsense.js` | developers.adnet.qq.com、u.kuaishou.com、www.csjplatform.com | 广告平台的域名（脚本分析它们用） |
| `UnblockURLinWeChat.js` | web.archive.org、webcache.googleusercontent.com、spotify.link | **它的功能就是"解开微信里被屏蔽的链接"**，必须去这些地方查 |
| **`bilibili.protobuf.request.js`** | **`bsbsb.top`** | ⚠️ **需要你知道**：这是作者自建的"跳过赞助片段"接口（`/api/skipSegments?videoID=...`），**会把你看的 B站视频 ID 发到那个服务器** |

**唯一需要你主动判断的就是最后那一行。** 它是 GET 请求、只带视频 ID、不带任何账号信息；
功能是"自动跳过 B站视频里的赞助片段"。**不接受这个取舍的话，不装 B站相关的脚本规则即可。**

### 3.3 静态审计的能力边界（我把话说清楚）

- 它能证明：**不存在**"自动把内容上传出去"的代码路径；**能列出**所有第三方目标域名。
- 它**不能**替代人工逐个审计每个脚本的意图。我没有对全部 83 个脚本做逐行的恶意代码审计。
- 缓解措施：**所有脚本都抓到了本仓库**（`vendor/`）。上游如果偷偷改脚本，
  会体现在 **git 历史**和**每次构建的报告**里 —— 而不是悄悄地在你手机上生效。
  这是"本地化"除稳定性之外的第二个价值。

## 四、按安全性从高到低，你的四个选择

| 方案 | 隐私风险 | 去广告效果 |
| :-- | :-- | :-- |
| **A. 只装域名层**（不装证书） | **无** | 大部分广告被拦；开屏广告、改包类去不掉 |
| **B. 域名层 + 只装你需要的 per-App 模块** | 低（解密范围 = 你选的几个 App） | 接近完整（推荐的平衡点） |
| **C. 域名层 + 总模块 + mitm-exclude 排除敏感 App** | 中 | 完整。注意总模块解密 1,010 个主机名 |
| **D. 全都装，不做排除** | 高 | 完整 |

**任何情况下都建议**：银行、券商、支付、以及涉及工作机密的 App，**不要解密** ——
这不是隐私问题，而是它们有证书校验，解密会让它们异常；同时也避免敏感流量被明文处理。

**这件事不需要你手工配置**：`module/mitm-exclude.srmodule` 里已经预置了 45 个域名
（工行/建行/农行/中行/交行/招行/邮储/浦发/兴业/民生/平安/广发/光大/中信/北京银行…
东方财富/富途/华泰/中信证券/招商证券/同花顺/雪球… 支付宝/财付通/银联…
钉钉/飞书/WPS/石墨/Zoom/Slack），**装到模块列表最下方就自动生效**。

要增删：临时用的在模块「编辑参数」里填 `-域名`，长期用的改仓库
`config/mitm-exclude.txt`（一行一个，可加注释）后重新构建。

## 五、怎么自己验证（别信我的话）

1. **看构建报告**：`build-report-scripts.md` 里有全部 83 个脚本的兼容性、网络 API、
   第三方域名清单；`build-report-verify.md` 里有隐私检查（节点/密码/令牌）的结果。
   这两份文件在 `release` 分支上也能直接看到。
2. **看 git 历史**：脚本都在 `vendor/` 里。想知道上游有没有改过某个脚本，
   看 `release` 分支的提交差异即可。
3. **自己查脚本**：所有脚本都在 `vendor/<作者>/<仓库>/<分支>/<原路径>`，
   保留了原始出处，可以直接打开看。
4. **在手机上看**：小火箭 →「数据」→「代理」的日志里，
   带 **`MITM`** 标记的请求就是正在被解密的 —— 你可以随时看到解密范围有多大。

## 六、我不会做、也做不到的事

- 我**不能保证**上游 15 个来源的规则内容永远无恶意。我能做的是：把脚本抓到本地、
  每次构建做静态审计、把第三方域名列出来、让任何改动都留在 git 历史里。
- 我**不能替你决定**要不要开解密。那是一个取舍：用一点隐私风险换取更干净的使用体验。
- 我**不会**在规则里加入任何采集、上报、回传的代码 —— 如果你在产物里发现这类东西，
  那一定是有人动了手脚，请立刻提 issue。

**最后一句**：这套东西的默认取向是**保守**——域名层不需要证书就能用，
模块层是可选加强。**能不开解密就不开，能少解密一个域名就少解密一个。**
